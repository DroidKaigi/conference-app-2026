# Navigation overview

Navigation is built on Navigation3, aiming for: **adding a destination does not edit the center, features do not depend on each other, and a screen's `NavEntry` and `NavKey` serializer cannot go unregistered.**

The design splits by concern:

- [Navigator](./navigation-navigator.md) — each feature's outgoing navigations as type-safe methods; commands applied to the back stack in one place
- [NavEntry aggregation (NavEntryProvider)](./navigation-entry-aggregation.md) — each feature contributes its `NavEntryProvider`; `NavDisplay` reads the merged result
- [NavKey serializer aggregation (NavKeySerializersProvider)](./navigation-navkey-serializers.md) — back-stack persistence; per-feature registration generated by KSP
- [Entry retention (RetainNavEntryDecorator)](./navigation-retain-entry-decorator.md) — keeps a screen's graph alive exactly as long as its `NavEntry`
- [Root NavEntry emulation (RootSceneStrategy)](./navigation-predictive-back-tabs.md) — back exits from the home root even with other tabs stashed beneath it
- [Root tab bar (RootTabSceneDecorator)](./navigation-root-tab-bar.md) — bottom bar and tab switching via `RootTabSceneDecorator`
- [List-detail scenes (ListDetailSceneStrategy)](./navigation-list-detail.md) — `ListDetailSceneStrategy` on large windows; the detail pane's back icon adapts via a `CompositionLocal`
- [Deep links (DeepLinkEffect)](./navigation-deep-links.md) — external navigation requests (widget taps, URLs) buffered in `DeepLinkStore` and applied with a synthesized back stack on cold start
